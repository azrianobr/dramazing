# 한 화를 만드는 과정

한 화는 콘티에서 완성본까지 12단계로 나뉩니다. 각 단계는 입력과 출력(작품 폴더의 어디에 두는지)만 정하며, 어떤 도구를 써도 됩니다.

| 단계 | 입력 → 출력 | 실측한 도구 | 다른 도구로 바꾸려면 |
|---|---|---|---|
| 대본, 콘티 쓰기 | 원문 → `script.json`, `storyboard.json` | Claude Code | SKILL.md를 읽을 수 있는 어떤 AI 어시스턴트든, 또는 사람이 직접 |
| 이미지 생성 | `tasks.json` → `sheets/*.png`, `frames/*/f*.png` | Codex CLI | `adapters/image.md` 참고: 어떤 이미지 도구든 수동으로, 또는 직접 쓰는 명령줄 연결 |
| 영상 생성 | 첫 프레임 + `prompts.json` → `video/E01-03/s1.mp4` | Grok 웹 | `adapters/video-other.md` 참고: Kling, Jimeng, Veo, Runway 등 |
| 편집, 자막 | 컷 → 완성본 | ffmpeg + whisper.cpp(오픈 소스) | 보통 바꿀 필요 없음 |

참고 수치: 《渡口(나루터)》 4화부터 6화까지는 Codex + Grok으로 화당 약 2~3시간이 걸렸고, Grok 주간 한도의 6%~12%를 썼습니다.

아래 명령은 모두 skill 루트 폴더에서 실행합니다. `W`는 작품 폴더, `EP`는 화 번호입니다.

```bash
W=works/my-drama; EP=1
```

## 두 관문

전체 과정에서 두 군데는 반드시 멈추고, 사용자가 보고 동의할 때까지 기다린 뒤 넘어갑니다.

1. **서사 미리보기**(4단계): 콘티 그림으로 가편집본을 만들어 이야기가 이해되는지 확인합니다. 화질만 보는 것으로는 부족합니다. 화면은 멀쩡한데 아무도 이야기를 이해하지 못한 일이 실제로 있었습니다. 정지 화면으로는 무엇이 문제인지 말하기 어려워하는 사용자도 있습니다(《渡口》 1화 리메이크 때 그랬습니다). 그럴 때는 물어보고 미리보기를 건너뛴 뒤, 시험 컷과 편집한 시퀀스로 검토합니다.
2. **시험 컷**(7단계): 얼굴과 대사가 있는 컷을 먼저 하나 생성해 화질, 입 모양, 목소리를 확인합니다. 매 화 합니다.

## 배우 라이브러리

작품이 많아지면 얼굴이 몇 개만 남기 쉽습니다. 옷과 제목이 바뀌어도 시청자에게는 같은 사람입니다. `works/_演员库/`(또는 공용 폴더)에 작품을 넘나드는 배우 라이브러리를 두고, 작품마다 즉석에서 얼굴을 만들지 말고 여기서 캐스팅합니다.

- **구조는 배우 → 배역입니다.** `cast.json`에서 배우마다 고정 예명, 프로필 시트 한 장(`sheets/<번호>.png`), 고정 목소리 샘플(`voices/<번호>.wav`)이 있고, 작품별로 맡은 배역 이름을 나열합니다. 한 배우가 여러 배역을 맡을 수 있습니다. 이름과 옷은 작품마다 바뀌고 얼굴과 목소리는 그대로입니다. 빈 템플릿은 `templates/<언어>/cast.json`.
- **프로필 시트**: 밝은 단색 배경 16:9, 왼쪽 정면 상반신, 오른쪽 위 정면·측면·뒷면 전신, 오른쪽 아래 웃음·분노·울음·무표정 네 가지. "예쁜", "잘생긴" 같은 말은 쓰지 않고, 한눈에 알아볼 특징 3–4개(얼굴형, 쌍꺼풀 유무, 피부색, 점, 흉터, 앞니 틈, 머리 모양)를 적어 `looks`에도 같이 넣습니다. 주연 얼굴만 "인플루언서가 아닌 드라마 배우처럼 보기 좋게"를 씁니다. 새 얼굴은 라이브러리 전체와 한 장에 모아 보고, 두 장이 같은 사람처럼 보이면 다시 만듭니다.
- **의상 테스트**: 라이브러리에 넣기 전에 프로필 시트를 참고 이미지 1로 걸고 전혀 다른 옷으로 한 장 만들어 얼굴과 체형이 그대로인지 봅니다. 달라지면 다시 만듭니다.
- **목소리**: `dub.py say --model design`으로 목소리 묘사에 맞춰 6–13초 샘플을 만들어 `voices/`에 둡니다. 이후 그 배우의 대사는 모두 `--model clone`으로 이 샘플을 복제합니다. 예전 작품에서 말한 적이 있으면 혼자 말하는 구간을 잘라 샘플로 씁니다.
- **캐스팅**: 스토리보드를 쓰기 전에 배역 성격과 나이로 배우를 고릅니다. 작품의 인물 시트 프롬프트에 "얼굴과 머리 모양은 참고 이미지 1의 사람"이라고 쓰고 프로필 시트를 건 뒤 `looks`의 특징 문장을 넣습니다. 고른 뒤 배역을 `cast.json`에 추가합니다.
- **의상은 사전을 보고 씁니다**(`docs/refs/AI短剧服装款式词典.md`): 부위별(깃, 소매, 상의, 겉옷, 하의, 신발, 액세서리, 머리)로 한 벌씩, "구체적인 색 이름 + 소재 + 스타일 이름"으로 쓰고 스타일 이름 뒤에 생김새를 한 문장 덧붙입니다. 예: "더비 슈즈(끈을 묶는 캐주얼 가죽 구두)". 모델이 드문 스타일 이름을 모를 수 있습니다. 신분은 낡은 정도로 보여 주고(빛바램, 보풀, 반듯하게 다림), 나이를 보여야 할 때는 "나이감·신분감 빠른 참조"를 봅니다. 보이는 옷만 쓰고 "병원" "학교" 같은 범주어, 브랜드, 로고는 쓰지 않습니다.
- **여성 신발은 "종류 → 굽 높이 → 앞코 → 장식과 소재" 순서로 씁니다**(`docs/refs/AI短剧女鞋高跟鞋款式.md`). 예: "아이보리 양가죽 포인티드 토 슬링백 펌프스, 6cm 스틸레토 힐". 펌프스는 뒤꿈치를 감싸고 뮬은 뒤가 비어 있으니 섞어 쓰지 않습니다. 신발은 화면에 들어오는 컷과 인물 시트의 전신 뷰에만 쓰고 근접 컷에는 쓰지 않습니다. 신발을 보여야 하면 차에서 내리며 발부터 딛기, 문으로 걸어 들어오기처럼 전신이나 앉아서 발이 보이는 컷을 짜고, 발에 오래 머무는 클로즈업은 찍지 않습니다.
- **양말과 스타킹은 "종류 → 두께(데니어) → 색 → 무광 또는 은은한 광 → 무늬" 순서로 씁니다**(`docs/refs/AI短剧袜子丝袜款式.md` ①–⑦). 예: "20데니어 살색 무광 팬티스타킹". 일상 장면에는 반드시 "무광"을 씁니다. "스타킹"만 쓰면 번들거리는 광으로 그려지기 쉽습니다. 스타킹의 색과 비침 정도는 의상 카드의 신발·양말 칸에 쓰고 모든 첫 프레임에 그대로 반복합니다. 겨울에는 "기모"를 쓰고 코트와 부츠를 함께 입힙니다. 일상 장면은 전신이나 미디엄 숏으로 찍고 다리 클로즈업은 찍지 않습니다. 남자는 구두에 검은 정장 양말, 검은 천신에 흰 면양말을 신깁니다. 롱 스타킹, 가터 스타킹, 망사, 유광, 큐빅, 흰 스타킹(⑧ A–E)도 일상 스타일과 똑같이 쓰며, 순서는 "스타일 → 데니어 → 색 → 광택 → 장식 → 밴드(레이스, 민자, 가터 클립)"입니다. 나이트클럽, 무도장, 데이트, 악역 여조연 장면에 씁니다. 수위를 정하는 것은 옷이 아니라 동작과 자세입니다: 동작은 평소처럼 줄거리대로 쓰고 ⑧F의 아슬아슬한 앵글과 자세는 쓰지 않습니다. 흰 스타킹과 오버니 삭스는 교복, 양갈래 머리, 앳된 차림과 짝짓지 않고, 인물의 성인 나이를 적습니다.
- **인물마다 의상 카드를 먼저 씁니다**(`docs/refs/AI短剧服装造型指南.md` 3.1): 주색·보조색·포인트색을 구체적인 색 이름으로 하나씩, 옷마다 소재와 핏, 안쪽부터 겉옷까지의 레이어, 신발의 낡은 정도, 액세서리는 3개 이하로 어느 손·어느 쪽인지, 생활 흔적(앉아서 생긴 주름, 해진 소맷부리), 금지 항목. 카드의 의상 문단이 확정되면 인물 시트와 모든 첫 프레임에 한 글자도 바꾸지 않고 그대로 붙이고, 극 전체에서 색 이름을 바꾸지 않습니다. 같은 장면에서 대립하는 두 사람은 색의 차갑고 따뜻함이나 밝고 어두움, 소재의 고급스러움으로 차이를 둡니다. 질감은 "천이 중력에 따라 늘어지고 무광, 피부는 부드러운 빛, 금속만 강한 하이라이트"로 쓰고 "고화질" "정교한"은 쓰지 않습니다. 참고 이미지를 여러 장 걸면 각각 무엇을 맡는지 씁니다: 프로필 시트는 얼굴과 머리만, 인물 시트는 옷의 핏과 배색, 장면 시트는 공간만.
- **캐스팅 후에는 인물 설정 이미지만 먼저 만들고, 사용자가 승인하면 장면·소품 설정 이미지와 첫 프레임을 만듭니다.** 《换号》에서는 의상, 체형, 배우가 세 번 바뀌어 첫 프레임 13장을 매번 다시 만들었습니다. 설정 이미지가 가장 싼 단계이니 인물을 확정하고 넘어갑니다.
- **의상은 기본적으로 한 단계 더 개방적으로, 패션 화보 수준으로 자세히 씁니다.** 사용자 11-01(《电视声》): 「옷이 다 너무 보수적이다, 규칙 안에서 조금 더 열어도 되고 관객도 좋아한다」. 장면에 맞으면 캐미솔, 짧은 치마·반바지, 어깨 노출, 맨다리, 몸에 맞는 옷 모두 쓸 수 있고 옷은 제대로 갖춰 입습니다. 의상 설정 카드에는 원단(오간자, 새틴, 잔골지), 구조(가는 어깨끈과 오프숄더 튤 겹침, 입체 재단, 러플 단, 가는 파이핑), 장식, 머리 장식과 장신구까지 씁니다. 「캐미솔, 반바지」만 쓰면 평범한 홈웨어가 나옵니다.
- **여주인공 스타일 화보를 한 장 더 만듭니다.** 설정 이미지가 확정되면 작품마다 여주인공의 전신 패션 사진을 한 장 만듭니다: 자연스럽게 선 자세, 따뜻한 측역광으로 머리카락과 옷감 윤곽, 85mm 인물 렌즈 느낌, 배경 적당히 흐림. 표지와 홍보 이미지로 씁니다. 사용자가 준 패션 화보 프롬프트에 배우 프로필 사진을 걸자 OpenAI에서 한 번에 통과했습니다(`works/电视声/_logs/test-fashion.txt`).
- **첫 프레임에서 얼굴에 부드러운 빛을 줍니다. 어두운 장면도 같습니다.** 「얼굴은 밝고 부드럽게, 측역광이 머리카락과 옷 윤곽을 그린다」고 써서 얼굴이 어두운 방에 묻히지 않게 합니다.
- **어두운 집 장면에서는 자연스럽게 앉은 자세를 쓰고, 양반다리·무릎 껴안기·웅크리기는 쓰지 않습니다.** 《电视声》 f1(심야 소파, 캐미솔과 반바지, 양반다리로 무릎을 껴안음)은 OpenAI 출력 단계에서 sexual로 막혔고, 비슷한 옷도 패션 화보의 선 자세로는 한 번에 통과했습니다. 수위는 옷이 아니라 자세와 맥락이 정합니다. 막히면 규칙대로 Grok으로 대신 만들고, OpenAI `fix`로 얼굴을 배우 얼굴로 되돌립니다.
- **OpenAI 이미지 수정이 계속 끊기면(`EOF`, 500) Grok 이미지 편집으로 대신합니다.** 《电视声》 f5는 EOF가 4번 연속 났습니다. Grok Imagine에서 「图片」(이미지)로 바꾸고 「质量 2.0」(품질 2.0)을 고른 뒤 원본을 올리고 영어로 「이것만 고치고 나머지는 그대로」를 쓰면 한 번에 나왔습니다. 받은 파일은 1008×1792라서 1152×2048로 키운 뒤 씁니다.
- **옷이 아닌 천은 누구의 옷과도 색과 질감이 겹치지 않게 합니다.** 《电视声》 소파의 오트밀색 니트 담요가 샤오치의 카디건과 같아서, 샤오원 다리에 덮이자 사용자는 「샤오치 옷을 다리에 덮었다」고 봤습니다. 담요는 소파 등받이에 접어 걸어 아무도 덮지 않게 하거나, 어떤 의상에도 없는 색으로 바꿉니다.
- **배우의 옷을 바꿀 때는 배우 라이브러리의 체형 묘사를 그대로 옮기고, "노출하지 않음", "과장하지 않음", "허리에 가로 주름" 같은 말을 넣지 않습니다.** 《换号》에서 몸에 붙는 니트 원피스로 바꾸자 사용자가 허리와 다리가 굵어졌다고 했습니다. 이런 말은 모델을 보수적이고 다부진 체형 쪽으로 끌고 갑니다. 몸에 붙는 옷이 체형을 가장 많이 드러내며, 문구 수정·미적 기준 참고 이미지·부분 축소로도 안 되면 더 날씬한 배우로 바꿉니다.
- **장면은 사전을 보고 목록으로 씁니다**(`docs/refs/AI短剧场景款式词典.md`): "아늑한" "고급스러운" 같은 형용사 대신 다섯 칸을 채웁니다. ① 시대, 지역, 계층 ② 어떤 방 ③ 구체적인 물건 5–8가지(벽, 바닥, 가구, 조명, 잡동사니 — 잡동사니가 있어야 사람이 사는 집처럼 보입니다) ④ 시간대와 빛이 들어오는 방향 ⑤ 아닌 것(모델하우스 아님, 읽을 수 있는 글자 없음, 서양식 인테리어 아님). 가구는 낡은 정도를 씁니다(칠이 벗겨짐, 누렇게 바램, 오래 씀). 문패, 간판, 현수막의 글자는 쓰지 말고 "읽을 수 있는 글자 없음"이라고 씁니다. 9부의 완성 조합 34개는 실험하지 않았으니 먼저 빈 장면 이미지를 뽑아 봅니다. 장면 설정 이미지에서 이 문단이 확정되면 모든 첫 프레임에 그대로 붙입니다.
- **장면 일관성**(`docs/refs/AI短剧场景一致性指南.md`): 장소마다 ENV-01, ENV-02로 번호를 붙이고 장면 블록 하나(배치, 문과 창, 빛의 방향과 색온도, 탁자 위 소품의 개수와 위치)를 써서 모든 첫 프레임과 설정 이미지에 그대로 붙입니다. 장면 설정 이미지는 사람이 설 모든 자리가 보이는 4분의 3 측면 광각으로 그립니다. 정면 그림은 카메라가 바뀌면 모델이 나머지를 짐작해야 합니다. 리버스 숏은 같은 설정 이미지에서 같은 날, 같은 빛으로 반대 각도 참고 이미지를 만들고, 구조가 서로 어긋나는 참고 이미지는 차라리 걸지 않습니다. 컷마다 누가 화면 왼쪽, 누가 오른쪽인지, 시선 방향, 전경 어깨가 누구 것인지 적고 "180도 규칙 지키기"만 쓰지 않습니다. 소품은 개수와 상태로 쓰고, 바뀌면 몇 번째 컷부터 어떻게 바뀌는지 씁니다. 모든 첫 프레임은 확정된 원본 설정 이미지나 전경에서 파생하고, 파생본을 다시 파생하지 않습니다. 몇 컷 뒤 같은 장소가 다시 나오거나 리버스 숏에서 방의 나머지 절반이 보이면 그 장소의 이전 스크린샷도 함께 겁니다.
- **새 배우의 프로필 시트는 참고 이미지 없이 처음부터 만들고, 프롬프트는 여섯 부분으로 씁니다**(`writing.md` 「인물 설정화 프롬프트는 여섯 부분으로 씁니다」). 기존 시트에서 몸매만 고치면(다리를 늘리고 허리를 줄이면) 하나를 고칠 때 다른 하나가 틀어집니다. 《改口费》 전에 다섯 번 고쳤지만 다리가 사람 같지 않아 사용자가 모두 통과시키지 않았고, 처음부터 한 번 만들자 통과했습니다. 몸매는 전체 인상 한 문장만 쓰고, 머리 대 몸 비율이나 다리 비율 같은 숫자는 쓰지 않습니다.
- **배역 설정 시트는 배우 기록이 아니라 작품마다 배역별로 만듭니다.** 세로 보드(메인 비주얼, 프로필 표, 얼굴·머리 특징, 전신 네 방향, 체형 참고, 표정 여섯, 디테일 클로즈업)이고, 「직업」에는 그 작품 속 배역의 직업을 씁니다. 나눠서 만든 뒤 붙입니다: 칸마다 따로 생성하고 프로필 시트를 걸어 얼굴을 고정하며, 디테일 클로즈업은 칸마다 한 장씩 주체를 가운데에 두고 만들고, 표의 글자는 코드로 조판합니다. 한 장에 모델이 글자를 쓰면 「臀宽」「鞋码」 같은 항목명을 자주 틀립니다.
- **계정 규칙은 `cast.json`의 `rules`에** 두고 캐스팅 때 하나씩 확인합니다. 예: "작품마다 주연 얼굴 여성 최소 한 명"(`lead: true`).

## 단계

### 1. 콘티 쓰기

`writing.md`에 따라 이번 화의 `script.json`과 `storyboard.json`을 씁니다(`ep: N`을 추가하고, 앞선 화는 그대로 둡니다). 다 쓰면 검증합니다:

```bash
node scripts/validate.mjs --work $W --ep $EP
```

- **추억·시대극에는 시대를 몰라도 이해되는 마무리 한 줄이 있어야 합니다.** 《地瓜干》을 대본대로 만들었더니 사용자가 「이 작품이 뭘 말하려는지 모르겠다」고 했습니다. 1975년에 흰 밀가루 찐빵이 귀했다는 것을 관객이 알아야만 성립하는데 마무리도 없었습니다. 2025년 결말을 붙이자 섰습니다. 노부부가 상다리 휘는 밥상 앞에서 여전히 찐빵을 반으로 갈라 건네고, 할아버지가 「五十年了，还是一人一半」라고 말합니다. 시대 디테일에 기대는 대본이면 콘티 전에 「배경을 모르는 관객도 알아볼까」를 먼저 묻습니다. 아니면 같은 두 사람의 '지금' 장면을 붙이고 한 줄로 짚습니다.
- **새 장면의 비트 번호는 1부터 세고, 새 인물은 `project.json`의 `characters`에 등록합니다.** 비트 번호를 전체 번호로 쓰면 자막이 빠지고, 등록하지 않은 인물은 제한 조건에 undefined로 나옵니다.

### 2. 이미지 생성

```bash
node scripts/frames.mjs plan  --work $W --eps $EP --force      # 작업 목록 생성(이미 있는 이미지는 완료로 기록, 다시 그리지 않음)
node scripts/frames.mjs batch --work $W --only "E0$EP-01/"     # 먼저 첫 세그먼트만 생성
```

먼저 첫 세그먼트를 봅니다: 의상, 배치, 장소가 앞 화와 이어지는지. 문제가 없으면 전부 생성합니다:

```bash
node scripts/frames.mjs batch --work $W
```

- 「참고 이미지 N장이 아직 생성되지 않았습니다」라는 안내가 나오면 한 번 더 실행합니다.
- 이미 있는 이미지를 다시 그리려면 `--redo`를 붙입니다. 한 곳만 고치려면 `fix`를 씁니다: `frames.mjs fix --work $W --target frames/E01-03/f2.png --prompt <파일>`. 원본이 자동으로 참고 이미지 1이 되고, 프롬프트에는 고칠 곳만 씁니다. 나머지를 그대로 두라는 문장은 `fix`가 붙입니다.
- 위치를 조금 고치는 일(문손잡이 높이, 소품 수십 픽셀 이동)은 `fix`를 쓰지 않고 픽셀을 직접 고칩니다. `fix`는 위치를 고칠 때 지나치기 쉽습니다. 《那个女生》 02-5 첫 프레임의 문손잡이가 너무 낮아 `fix`를 두 번 돌렸더니 한 번은 조금만, 한 번은 너무 높게 옮겨졌고, PIL로 손잡이 부분을 잘라 정상 높이에 붙이자 한 번에 됐습니다. 고치기 전에 원본을 `_bak/versions/`에 복사해 둡니다.
- 앵글 고르기(선택): 설정화나 첫 프레임이 나온 뒤 `frames.mjs grid --work $W --from frames/E01-03/f1.png --name corridor`로 16:9 격자 한 장을 `_handoff/grid/corridor.png`에 뽑습니다. 행은 카메라 높이(기본 눈높이, 로우, 하이), 열은 숏 크기(기본 원경, 미디엄숏, 클로즈업, 익스트림 클로즈업)이며 `--rows`, `--cols`로 바꿀 수 있습니다. 고른 뒤 콘티의 `angle`과 `size`를 고치고 그 컷만 다시 그립니다. 어느 한 칸의 앵글대로 그리게 하려면 `frames.mjs grid --work $W --name corridor --crop 2,3`으로 2행 3열을 잘라 `fix --ref`나 수동 생성의 참고로 씁니다. 칸마다 약 418×314밖에 안 되니 앵글 고르기에만 쓰고 첫 프레임으로 쓰지 않습니다. tasks.json은 건드리지 않습니다.
- 이미지 생성 방식은 `--provider` 또는 `project.json`의 `images.provider`로 정합니다: `manual`(기본값. 안내문을 내보낸 뒤 어떤 도구로든 그리고 `place`로 되돌려 넣음), `cmd`(직접 쓰는 명령줄 연결), `codex`, `openai`(OpenAI 이미지 API). `adapters/image.md`를 참고하세요.

### 3. 이미지 확인

얼굴만 보지 말고 모든 이미지를 화면 전체로 봅니다. 흔한 문제:

- 있어서는 안 될 사람이 한 명 더 있다(전경에 흐릿한 어깨 하나도 해당).
- 인물이 앳되어 보인다.
- 배경이 시대나 지역과 맞지 않는다.
- 소품 상태가 `blocking`과 다르다.
- 손과 발: 사람마다 손이 몇 개인지 세고, 좌우 발과 좌우 손이 맞는지 본다. 앉은 자세에서 가장 잘 틀린다(《老地方》 E01-01/f7 손 세 개, 확정한 뒤에야 발견).
- 분장 세부: 설정화와 대조해 매니큐어, 반지, 장신구를 확인한다. 첫 프레임에서 빠지면 영상도 그대로 따라 한다(《老地方》 20장 중 3장의 손톱이 맨손톱 색으로 그려져 4번 재작업).

### 4. 서사 미리보기(관문 1)

```bash
python3 scripts/preview.py --work $W --ep $EP
```

`video/E0N.preview.mp4`를 출력합니다. 컷마다 콘티 그림이 정해진 초만큼 머물고, 아래에 대사가, 왼쪽 위에 컷 번호가 표시됩니다. 사용자에게 보여 주고 이야기가 이해되는지 확인합니다.

사용자가 정지 화면으로는 판단이 안 된다고 하면 미리보기를 더 만들지 않습니다. 시험 컷을 한두 개 더 만들어, 동선이나 장소 문제를 움직이는 영상에서 확인합니다.

### 5. 프롬프트 생성

```bash
node scripts/video-prompts.mjs --work $W --ep $EP --target grok   # 또는 generic, 또는 직접 쓴 targets/<도구>.mjs
```

파일 두 개를 쓰고, 사전 점검 경고를 함께 출력합니다:

- `video/shots.json`: 컷 설명(동작, 시선, 카메라 움직임, 대사, 제약). 어떤 영상 도구를 쓰든 상관없습니다.
- `video/prompts.json`: 대상 도구에 맞게 만든 프롬프트와 길이 단계.

이미 있는 항목은 덮어쓰지 않으므로, 프롬프트를 손으로 고친 뒤에도 안심하고 다시 실행할 수 있습니다. 도구를 바꿀 때는 `--force`를 붙여 다시 만듭니다.

### 6. 프롬프트 한 개씩 검토

첫 프레임과 대조하며 하나씩 봅니다:

- 동작 방향이 첫 프레임과 맞는지.
- 누가 화면에 나오고 누가 말하는지.
- 속마음 컷에서 말하는 사람이 정면이고 입을 다물고 있는지.
- 카메라 움직임에 끝점이 적혀 있는지.

규칙은 `prompt-rules.md`를 보세요.

### 7. 시험 컷(관문 2)

얼굴과 대사가 있는 컷 하나를 골라 먼저 생성합니다. 가능하면 이번 화에서 새로 나오는 것, 즉 새 인물, 새 소품, 새 카메라 움직임도 함께 시험합니다. 사용자에게 보여 주고, 통과하면 일괄 생성합니다.

### 8. 영상 생성

영상 도구에서 하나씩 생성합니다: 첫 프레임을 올리고, `prompts.json`에서 해당 항목의 `prompt`를 붙여 넣고, 길이는 `seconds`로 고릅니다. 내려받은 파일 이름에는 컷 번호를 넣습니다. 예: `E01-03-s1.mp4`(앞에 도구 이름을 붙여도 됩니다).

- Grok: `adapters/video-grok.md` 참고(실측함).
- 다른 도구: `adapters/video-other.md` 참고(미실측. 1화에서 시험 컷을 몇 개 더 생성하세요).

영상 생성 전, 일괄 생성을 마친 뒤, 재작업 뒤에 각각 한 번씩 사용량(한도 비율, 크레딧 또는 비용)을 기록해 `_logs/usage.tsv`에 적습니다.

### 9. 영상 수집

```bash
bash scripts/ingest.sh $W            # 기본값은 ~/Downloads에서 수집. 다른 폴더는 두 번째 인자로 지정
bash scripts/ingest.sh $W --file ~/Downloads/<내려받은 파일>.mp4 E01-03-s2   # 파일 이름에 컷 번호가 없을 때(예: 페이지 다운로드 버튼이 대화 ID로 이름을 붙일 때) 컷을 직접 지정
```

파일 이름에 `E01-03-s1`이 들어 있는 영상을 `video/E01-03/s1.mp4`로 옮깁니다. 같은 이름의 컷이 이미 있으면 기존 파일은 `s1.old.mp4`로 이름을 바꾸고 재작업 1회로 기록합니다.

수집이 끝나면 먼저 확인합니다: 모든 컷에 영상이 있는지, 영상이 콘티 그림과 맞는지. 일괄 제출할 때 빠뜨린 적이 있습니다.

**난데없이 생긴 것이 없는지 프레임 단위로 봅니다.** 영상 모델은 동작 중에 없던 소품을 그려 넣기도 합니다. 《加油》 E01-03/s1에서는 발을 구른 뒤 신발 한 짝이 계단 아래로 날아갔습니다. 0.4초만 보여서 0.5초 간격으로 뽑은 프레임에서는 놓쳤습니다. 편집에 쓸 구간은 초당 8프레임 이상으로 프레임 시트를 만들고, 손발 동작과 소품을 주고받는 앞뒤를 특히 봅니다.

```bash
ffmpeg -ss 2 -to 4 -i $W/video/E01-03/s1.mp4 -vf fps=12,scale=270:-1,tile=6x4 /tmp/E01-03-s1.png
```

고정 카메라 숏이라면 다시 생성하지 않고 깨끗한 프레임으로 그 부분을 덮을 수 있습니다.

### 10. 편집, 검수

```bash
python3 scripts/cut.py --work $W --ep $EP                                 # 세그먼트별로 편집
node scripts/assemble.mjs --work $W --ep $EP --loudnorm --align --no-burn # 한 화로 이어 붙이고 자막 정렬
python3 scripts/review.py --work $W --ep $EP                              # 검수본: 왼쪽 위에 컷 번호 표시
```

- `cut.py`는 whisper로 대사가 끝나는 시점을 재고, 최소한 대사가 끝날 때까지는 남깁니다.
- 수동 편집점은 `video/fix.json`에 적습니다: `{"E01-06": {"fix": {"1": 4.0}, "skip": [2], "in": {"3": 1.25}, "speed": {"4": 1.6}, "subs": {"대본 원문": [시작, 끝]}}}`(`subs`는 아래 「손으로 고친 자막 시간」 참고). `fix`에 적은 컷은 줄이지 않습니다. `fix`는 가속 후 완성본의 초이며, 그 컷도 `--rate`로 자동 가속됩니다. 배율을 고정하려면 `speed`에 적습니다. `in`은 원본 클립의 몇 초부터 쓸지입니다. 동작이 프롬프트보다 늦게 나오면(등불이 1초 늦게 꺼지는 경우 등) 다시 생성하지 말고 뒷부분을 씁니다.
- 프레임을 뽑아 확인할 때는 언제나 화면 전체를 보고, 얼굴만 잘라 보지 않습니다.
- 사용자는 번호(예: `06-2`)로 의견을 줍니다. 재작업은 먼저 예비로 받은 두 번째 영상이 있는지 보고, 없을 때만 다시 생성한 뒤 9단계로 돌아갑니다.
- **제작 도중 컷을 더할 때**(검토 후 설명이나 리듬을 보충해야 할 때): 먼저 새 컷을 `storyboard.json`에 넣고, 파일 이름을 손으로 바꾸지 말고 `renumber.mjs`로 뒤 컷 번호를 한꺼번에 미룹니다. 첫 프레임, 원본 영상, `fix.json`, `prompts.json`, `shots.json`의 번호를 함께 바꿉니다. `prompts.json`과 `shots.json`이 옛 번호로 남으면 `cut.py`가 대사를 엉뚱한 숏에 맞춰 편집 길이가 틀어집니다(《真的》). 바꾼 뒤에는 안내대로 작업 목록을 다시 만들고 새 프롬프트를 채웁니다. 컷 하나를 빼려면 번호를 바꾸지 말고 `fix.json`의 `skip`에 그 번호를 씁니다.

  ```bash
  node scripts/renumber.mjs --work $W --seg E01-03 --insert 2 --count 2 --dry   # 먼저 바꿀 것을 확인
  node scripts/renumber.mjs --work $W --seg E01-03 --insert 2 --count 2         # 옛 2번 컷부터 번호를 2씩 미룸
  ```
- **박힌 자막이 움직이지 않는 어두운 곳(옷, 벽)에 있으면 깨끗한 프레임으로 그 부분만 덮습니다.** 자막이 나타나고 사라지는 시간과 범위를 프레임마다 찾고, 입을 열기 전 프레임에서 그 부분을 잘라 그 프레임들에만 `overlay`로 덮습니다. 원본은 `_bak`에 둡니다. 입 모양이 남아서 상대 반응으로 덮는 것보다 낫습니다(《赊账》 s5 「挺好」가 두 번 다 가슴 쪽 스웨터에 박혀, 220×140 조각을 0.2–0.95초 덮었더니 티가 나지 않음). 자막이 얼굴이나 움직이는 곳에 있으면 다음 항목대로 합니다.
- **한 사람 짧은 대사 숏이 자꾸 자막을 박아 넣으면, 그 숏의 소리만 씁니다.** 표현을 바꿔 두세 번 다시 만들어도 자막이 박히면, 그 컷의 화면을 `cover`로 상대의 반응 숏으로 덮고 소리는 그대로 씁니다. 전화 장면은 흔히 이렇게 편집합니다. 관객은 한쪽의 말을 들으며 다른 쪽의 반응을 봅니다(《跟谁吃的》 02-3 「我都快到家了」는 세 번 모두 자막이 박혀, 그가 미간을 찌푸리는 반응으로 덮음). 덮는 소재는 프레임마다 표정을 확인합니다. 클립 후반에 웃음이 섞이는 일이 많습니다.
- **손으로 고친 자막 시간은 `fix.json`에 저장해 다시 이어 붙여도 잃지 않습니다.** `assemble.mjs`는 실행할 때마다 콘티 비트(또는 `--align`의 whisper)로 `E0N.srt`를 다시 배치하고, 잘못 배치된 줄(인식 실패, 무음 판단 오류)은 손으로 고쳐야 합니다. `E0N.srt`를 고친 뒤에는 **다시 자르기 전에** `assemble.mjs … --keep-subs`를 한 번 실행합니다. 고친 줄을 대본 원문으로 찾아, 그 줄이 있는 컷의 편집점부터 센 초로 바꿔 `fix.json`의 그 구간 `subs`에 씁니다(`{"E01-02": {"subs": {"哎呀老公，我把你落在餐厅了！": [2.55, 5.25]}}}`). 이후 다른 컷이 길어지거나 짧아져도, 한 화를 다시 이어 붙여도 이 줄들은 자기 컷을 따라갑니다. 대본 원문이 바뀐 줄은 맞지 않으므로 경고를 출력합니다(《跟谁吃的》는 세 번 다시 이어 붙이며 매번 자막을 손으로 되돌려야 했고, 그 뒤에 이 옵션을 추가함).
- 뒷부분의 흠은 잘라 내는 편이 다시 생성하는 것보다 쌉니다. 흠이 늦게 나타나고 대사가 이미 끝났다면 `fix.json`에서 그 컷을 짧게 줄입니다.
- **대사 중간의 긴 멈춤은 잘라 내고, 이음매는 삽입 숏으로 덮습니다.** `cut.py`는 앞뒤만 자를 수 있습니다. 먼저 ffmpeg로 원본 영상에서 멈춤을 잘라 내고(약 0.25초 남기고, 화면과 소리를 함께 자르고, 다시 인코딩), 원본은 `_bak/video/`에 따로 보관합니다. 그다음 콘티의 `cover`로 이음매를 삽입 숏 안에 덮고, 원래 따로 있던 삽입 숏은 `skip`에 씁니다(《老地方》 01-2: 1.6초 멈춤을 결혼반지 클로즈업으로 덮음).
- `speed`는 그 컷의 가속 배율입니다. 화면과 소리가 함께 빨라지고 음높이는 그대로입니다. 세로 숏폼은 `writing.md` 5절의 리듬을 따릅니다: 동작만 있는 숏은 ×1.4–2.0. Grok 원래 목소리를 쓰는 대사 컷은 기본 ×1.3입니다: 《改口费》를 1.0으로 편집하자 사용자가 「말이 너무 느리다」고 했고, 대사 컷을 1.3으로 올리자 통과했습니다. 말이 없는 반응 컷은 1.0으로 두어 관객이 반응할 시간을 줍니다. 화면 속 입이 원래 빨리 움직이는 컷(《改口费》 s2, s8)도 화면을 1.0으로 둡니다. 프롬프트에 말 속도 단어를 써도 거의 소용없습니다: 《赊账》 시험 s6에 「talking fast and sharp, quick snappy delivery」를 썼지만 클립은 조금만 빨라졌고 사용자가 두 번 느리다고 했습니다. 1.3배로 자르고서야 통과했습니다. 시험 컷은 1.3배로 잘라서 들려줍니다.
- **소리와 화면이 맞는지 확인합니다.** `cut.py`와 `assemble.mjs`는 출력할 때마다 오디오와 영상의 길이를 비교하고, 0.25초 넘게 차이 나면 멈춥니다. 전체 길이로는 중간의 어긋남을 잡지 못하므로, 후반 작업을 따로 할 때는 다음도 확인합니다.
  1. `ffprobe`가 알려 주는 오디오와 영상의 스트림 길이를 봅니다. 프레임 수를 24로 나누지 않습니다. 가변 프레임레이트 파일에서는 틀립니다.
  2. 화면과 소리가 함께 바뀌는 곳을 몇 군데 찾습니다. 예를 들어 컷이 바뀌며 대사가 시작되는 곳, 발을 구르자 불이 켜지는 곳입니다. 프레임은 프레임 번호가 아니라 시간으로 뽑고(`ffmpeg -ss 초`), 소리의 시작은 음량 곡선에서 찾습니다. 둘이 한 프레임 안에 떨어져야 합니다.

  자막 시간을 음량 곡선에 맞춰 보는 것은 확인이 아닙니다. 둘 다 계획한 시간으로 배치했으므로, 맞아도 서로 일관된다는 뜻일 뿐입니다. 《加油》 첫 버전은 이렇게 해서 0.3초 어긋남을 놓쳤습니다.

  **이어 붙일 때의 함정.** 구간 파일의 오디오 타임스탬프는 실제 소리와 다를 때가 많습니다. 컨테이너에는 22.3초로 적혀 있는데 디코딩하면 22.229초뿐입니다. 타임스탬프대로 이어 붙이면(concat 목록, `aresample`로 메워도 마찬가지) 뒤로 갈수록 소리가 빨라지거나 늦어집니다. `assemble.mjs`는 구간마다 화면을 n프레임으로 채우거나 자르고, 소리를 샘플 수로 같은 n/24초에 맞춘 뒤, 두 트랙을 각각 이어 붙입니다. `cut.py`도 구간 안에서 숏마다 같은 일을 합니다. 길이를 1/24초 단위로 반올림하고, 화면을 그 프레임 수로, 소리를 같은 길이로 채우거나 자른 뒤 이어 붙입니다. 이렇게 하지 않으면 빨리 감은 숏 뒤로 화면이 점점 늦어집니다. 《大水》 1구간 끝에서는 소리가 화면보다 약 0.1초 빨랐습니다. 화면의 빈틈을 메우려고 프레임 번호로 타임스탬프를 다시 쓰고 고정 프레임레이트를 강제하지 않습니다. 프레임이 빠집니다. 《加油》 네 번째 버전에서 이렇게 해서 뒤쪽 276프레임을 잃었습니다. `cut.py`는 컷마다 오디오 끝에 `asetpts=N/SR/TB`를 붙여 샘플 수로 타임스탬프를 다시 계산합니다: `loudnorm`을 거친 컷은 오디오 타임스탬프가 한 번 튀고, `concat`이 그만큼 다음 컷을 약 2프레임 뒤로 밀어 편집점에 빈틈이 생기며 뒤쪽 자막이 점점 늦어집니다(《改口费》 끝에서 0.58초, 《干拌吗》에도 있었음).

  **먼저 Grok 원래 목소리를 씁니다.** 《改口费》에서 같은 편집의 MiMo 더빙판과 Grok 원음판을 비교하자 사용자가 「Grok 원음 완승」이라고 했습니다. Grok은 목소리와 입 모양을 함께 만들어 말투도 더 사람 같습니다. 원음이 글자를 빼먹거나 잘못 읽으면 먼저 그 컷을 다시 제출합니다(《改口费》 s6에서 「爸妈」의 「爸」가 빠졌고, 다시 낸 두 벌은 모두 제대로 말했습니다). 다시 내도 안 되거나 기존 배우 목소리를 꼭 써야 할 때만 더빙합니다. 더빙할 때 세 가지:
  - `--style`은 몇 단어만 씁니다(「놀람, 반가움」). 길게 쓰면 복제한 목소리에 억양이 생겨 사용자가 「외국인이 중국어 하는 것 같다」고 했습니다.
  - `--model design`으로 만든 샘플은 실제 녹음이 아니라서 복제하면 억양이 틀어지기 쉽습니다. 복제 전에 짧은 대사 하나를 사용자에게 들려 줍니다.
  - 대사마다 3벌을 만들고 자연 길이가 입 모양에 가장 가까운 것을 고르며, `fit` 늘이기·줄이기는 0.85–1.15배 안에 둡니다. 1.3배 이상 줄이면 소리가 가늘게 들립니다.
- **더빙 교체: 화면과 입 모양은 Grok, 목소리는 MiMo로 복제(선택).** Grok이 글자를 잘못 읽을 때(《干拌吗》에서 「蚯蚓」을 「手引」으로 읽음), 목소리가 맞지 않을 때, 기존 배우의 목소리를 그대로 써야 할 때 씁니다. 에피소드 단위 `mute: true`로 Grok 소리를 끄고, 대사마다 에피소드 단위 `audio`에 한 줄씩 겁니다. 순서:
  1. 샘플 자르기: 그 배우가 예전에 혼자 말한 컷에서 5–10초를 자릅니다. 그 사람 목소리만 있고 음악이나 다른 사람 목소리가 없어야 합니다. 여러 조각을 잇고 중간 무음은 지웁니다.
  2. 더빙 만들기: `python3 scripts/dub.py say --model clone --voice ref-C01.wav --style "말투" --text "대사" -o L1.wav`, 대사마다 두 벌씩 만듭니다. `--model design`은 글로 묘사한 새 목소리를, `--model tts`는 프리셋 목소리를 씁니다. 키는 환경 변수 `MIMO_API_KEY`에서 읽습니다. 한 번에 한 건씩 보냅니다. 동시에 보내면 제한(429)에 걸립니다.
  3. 입 모양 재기: `dub.py segs video/E01-01/s3.mp4`가 Grok이 대사마다 입을 열고 닫는 초를 알려 줍니다.
  4. 맞추기: `dub.py fit L1.wav --from 시작 --to 끝 --dur 입모양길이 -o audio/dub/L1.wav`. 늘이고 줄이는 배율이 0.75–1.35를 넘으면 다른 벌을 쓰거나 컷 지점을 바꿉니다. `at` = 그 컷의 에피소드 안 시작점 + 입 여는 초 − `fix.json`의 `in`.
  5. 자막은 더빙이 실제로 나오는 시간에 맞춰 `E0N.srt`를 고친 뒤 `--keep-subs`를 실행합니다.
  6. 더빙을 받아써서 글자를 확인합니다. Grok 발음을 확인하는 것보다 믿을 만합니다. 목소리가 닮았는지는 사용자에게 들려 줍니다.
- **소리로 반전하는 이야기는 소리를 전부 후반에 만듭니다.** 《电视声》의 반전은 「일시정지 후 스피커폰 속 TV 소리가 한 박자 늦게 멈춤」입니다. TV 화면은 화면에 넣지 않고(카메라에 옆면, 얼굴에 비친 빛만), Grok 프롬프트에는 「no TV sound」를 씁니다. 방송은 MiMo로 뉴스 앵커 목소리를 만들고 후반에서 두 층을 섞습니다: 방 TV는 처음부터 끝까지, 대사가 있으면 sidechain으로 낮춤; 스피커폰은 같은 방송을 0.15초 늦게, 전화 필터(450–3200 Hz)를 걸어 스피커를 켠 프레임부터. 일시정지 프레임은 한 프레임씩 보며 정하고, 방 TV는 그 자리에서, 스피커폰은 약 0.3초 뒤에 멈춥니다. 방 쪽이 스피커폰보다 약 9 dB 커야 두 번 멈추는 게 들립니다. 믹스 스크립트가 `video/E01-01.shots.json`에서 각 컷 시작을 읽으니 편집 길이가 바뀌어도 손으로 다시 맞출 필요가 없습니다(`works/电视声/_logs/mix-tv.sh`).
- **열린 질문으로 끝나도 마무리 컷이 필요합니다.** 《十八万八》 원래 대본은 李娟의 반문 「那结了婚，我住毛坯房？」 직후 바로 암전했고, 사용자가 「끝이 너무 성의 없고 갑자기 끊긴다」고 했습니다. 반문이나 질문 뒤에는 질문받은 사람의 말 없는 반응(약 2초: 입을 열었다 닫고, 눈을 내리깔고, 손에 힘을 줌)을 붙이고, 이어서 뒤로 빠지는 와이드(약 3초: 두 사람이 각자 다른 곳을 보고 카메라가 천천히 물러남)를 붙인 뒤 암전합니다. 질문에는 여전히 답하지 않지만 관객이 삼킬 시간이 생깁니다. 착지 점검 때 물어보세요: 마지막 대사 뒤 화면은 어디서 멈추는가?

- **AI 배우는 음정에 맞춰 노래하지 못합니다. 노래 장면은 녹음 재생이나 말로 바꿉니다.** 《生日》 대본은 라이더가 계단에서 생일 축하 노래를 부르는 장면이었습니다. Grok이 두 번(두 번째는 한 줄만, 천천히, 한 음절에 한 음), MiMo가 한 번 불렀는데 모두 음정이 틀렸고 사용자가 「노래가 완전히 틀렸다」고 했습니다. 라이더가 휴대폰으로 오르골 생일 노래를 틀어 주는 것으로 바꿨습니다: 악보대로 사인파로 합성(퍼블릭 도메인 선율)하고 500–4500 Hz로 걸러 휴대폰 스피커 소리로 만든 뒤 후반에 그 컷에 섞습니다. - **컷이 짧아진 뒤 `--keep-subs`는 예전 자막 시간을 그대로 쓴다.** `fix`를 바꾼 뒤에는 새 컷 지점에 맞춰 자막 시간을 다시 쓰고 조립한다 (《两千件》).
- **원본 잡음을 먼저 줄이고 자릅니다.** Grok 원본에는 바람, 매미 소리가 자주 섞이고, `--loudnorm`이 컷마다 평준화하면서 대사 사이 공백도 -43 dB 안팎까지 끌어올려 사용자가 알아챕니다(《地瓜干》). 원본 오디오에 `highpass=f=90,afftdn=nr=24:tn=1`을 걸고 화면은 `-c:v copy`, 원래 소리는 `_bak/versions/`에 둡니다. 공백이 6–10 dB 내려가고 전사는 영향이 없습니다. 프롬프트에도 환경음을 적게 씁니다.
- **시대를 건너뛸 때는 전환 효과를 넣습니다.** 《地瓜干》 1975→2025를 하드컷했더니 사용자가 효과를 원했습니다. 앞 컷 끝 약 0.9초를 누렇게 바랜 옛 사진(세피아 행렬, 그레인, 비네트, `rgb24`에서 처리; yuv나 gbrp에서 하면 푸르스름한 회색이 됨)으로 바꾸고, 0.8초 흰 섬광(`transition: fadewhite`)으로 새 시대에 들어가며, 연도 자막은 흰빛이 걷힐 때 서서히 나타나게 합니다.
- **첫 프레임과 완성본에서 발을 확인합니다.** 《地瓜干》 s13에서 두 사람이 맨발이었는데 전경에서는 검은 헝겊신을 신고 있어, 아래 14%를 잘라 맞췄습니다.
- **채팅 메시지에는 보이스오버를 넣습니다.** 말풍선만 있으니 사용자가 화면이 너무 조용하다고 했습니다(《换号》). 낯선 사람이나 사기꾼은 출연진 누구와도 닮지 않은 목소리로 만들고(MiMo design, "발음이 또렷하게"라고 씁니다. "목소리를 낮춰"라고 쓰면 글자가 뭉개집니다), 휴대폰 스피커 음색으로 처리합니다: `highpass=f=300,lowpass=f=3600`, 약 +7 dB. 극중 인물이 보낸 메시지는 그 인물의 복제 목소리를 씁니다. 보이스오버는 말풍선과 동시에 나오게 하고, 한 줄씩 전사해 글자를 확인합니다.
- **극중 인물이 메시지를 소리 내어 읽으면 말풍선에 보이스오버를 따로 넣지 않습니다.** 《李总》에서 小周가 읽는 동안 말풍선이 뜨니 그녀의 목소리가 보이스오버입니다. 말풍선은 휴대폰 옆(`x 0.40, y 0.66`, 꼬리는 그녀 쪽)에 둡니다. 처음에 `y 0.5`로 두었더니 얼굴 옆을 가렸습니다.
- **유리 너머 대사는 로우패스.** 원음에 `lowpass=f=2200,volume=0.8`을 걸면 한 겹 너머 소리가 되고 입 모양은 그대로입니다(《李总》 s13).
- **반전이 "뒤돌아봐"라면 첫 컷부터 답을 화면에 넣습니다.** 반전 인물을 모든 컷에서 주인공 뒤에 두고, 단독 리버스에서도 흐릿하게 남깁니다. 돌아보는 동작은 찍지 않고 그녀의 움직이지 않는 뒤통수 너머로 뒤쪽을 봅니다(Grok은 지정한 고개 돌리기를 따르지 않음). 《李总》에서 李总은 S01부터 유리 안에서 도시락을 먹습니다.
- **2인 와이드 컷도 두 사람 손에 할 일을 줍니다.** 와이드 대사도 자막이 박힙니다(《李总》 s1 전체). 말하는 사람과 듣는 사람의 손 위치를 모두 쓰고, 대사의 띄어쓰기를 없앱니다.
- **대본의 직업 동작은 랜딩 체크에서 현실과 맞춰 봅니다.** 《面试》 대본의 「陈静低头写」를 그대로 종이에 프로그래밍하는 장면으로 그렸더니, 사용자가 「프로그래밍을 왜 종이와 펜으로 하냐」고 물었습니다. CNC 프로그래밍, 장부, 디자인, 표 작업은 지금 컴퓨터로 합니다. 컴퓨터를 장면과 첫 프레임에 넣고, 화면은 카메라를 향하지 않게(옆에서 모서리, 어깨 너머로 뒷면) 하고 대사 후 덮습니다.
- **Grok이 어떤 글자를 계속 틀리게 읽으면 대사에 동음자를 씁니다.** 《面试》에서 「螺丝」가 두 번 「罗席」「罗系」로 전사됐고, `luó sī` 주석도 소용없었습니다. 대사를 「拧螺思的」로 쓰자 바로 읽었습니다. 자막은 원래 단어로 씁니다. 같은 단어가 두 번 틀리게 전사되면 잘못 읽은 것으로 보고 바로 글자를 바꿔 다시 만듭니다. 사용자에게 듣기만 부탁하지 않습니다.
- **스토리보드 화면을 고쳤으면 작업 목록을 다시 만든 뒤 첫 프레임을 다시 뽑습니다.** `frames.mjs`는 `tasks.json`에 저장된 설명으로 그립니다. `storyboard.json`을 고친 뒤 `plan --work $W --eps $EP --force`, 그다음 `batch --only '/fN$' --redo`. 《面试》는 `--force`, 다음엔 `--eps`를 빠뜨려 옛 설명으로 4장을 헛되이 뽑았습니다.
- **세로 표지는 자막 없는 `video/E0N.mp4`에서 캡처합니다.** `E0N.final.mp4`와 완성본에는 자막이 박혀 있습니다.
- **어깨 너머 숏 가장자리의 인물은 「끝까지 움직이지 않고 얼굴이 화면에 들어오지 않는다」고 씁니다.** 「돌아보지 않는다」만으로는 부족합니다. 《몽유》 s3에서 오른쪽 가장자리의 흐린 룸메이트가 1초부터 안으로 고개를 들이밀어 얼굴 반쪽이 보였고, 사용자는 섬뜩하다고 했습니다. 머리카락과 어깨만 보이고, 끝까지 가만히 있으며, 몸을 기울이거나 고개를 움직이지 않고, 얼굴이 화면에 들어오지 않는다고 적습니다. 다운로드 후 검사할 때도 자막과 좌우 위치만 보지 말고 가장자리를 봅니다.
- **화면 속 영상(CCTV, 휴대폰 영상)은 전체 화면 인서트 숏으로 따로 찍습니다.** 화면을 찍지 않습니다. 이상한 글자가 생깁니다. 타임코드와 카메라 번호는 후반에 drawtext로 넣고, 원본이 무음이면 환경음을 섞습니다. 「돌아서서」 얼굴을 보여야 하면 뒷모습 숏과 카메라 쪽으로 걸어와 고개를 드는 숏으로 나누고, 제자리 회전은 쓰지 않습니다.

- **신발 신기처럼 소품을 다루는 동작은, 소품이 내내 손에 있다고 씁니다.** 《鞋垫》 s12 첫 버전에서 신발이 바닥에 떨어졌다가 다음 순간 발에 신겨 있었습니다. 「신발은 내내 손에 들고, 내려놓거나 떨어뜨리지 않으며, 깔창을 편 다음 말한다」로 바꾸자 두 번째 버전이 맞았습니다.
- **첫 프레임 가장자리에 얼굴이 보일 때의 수습: 그쪽을 잘라 내고 원래 크기로 키웁니다.** 《鞋垫》 s13 첫 프레임 오른쪽 위에 차오윈의 흐린 반쪽 얼굴이 보였습니다(첫 프레임 검토 때 또 놓쳤고, 《每月两千》 s13과 같은 실수입니다). 다시 제출하지 않고 오른쪽을 약 11% 잘라 1080×1920으로 키우자 얼굴이 화면 밖으로 나갔습니다. 대가는 화면이 조금 무르고 구도가 빡빡해지는 것입니다. 자를 수 있으면 다시 제출하지 않지만, 첫 프레임 검토 때는 여전히 가장자리부터 봅니다.
- **자막을 옮긴 뒤에는 컷마다 프레임을 뽑아 확인합니다.** 《鞋垫》는 자막을 컷에 맞춰 옮겼고 사용자도 검토에서 알아채지 못했습니다. 숏 분석에서야 S14 끝 프레임에 다음 줄 「说穿上了 不冷」이 0.2초 일찍 차오윈 얼굴 위에 뜬 것이 보였습니다. 조립한 뒤 컷마다 0.15초 전 프레임을 하나 뽑아, 화면 속 자막이 지금 화면에 있는 사람의 대사인지 봅니다.
- **대사 없는 컷은 배경 소음으로 바꿉니다.** Grok은 대사 없는 컷에 영어 한 마디를 스스로 넣는 일이 잦습니다(《换号》 s5, s13 두 번). 입이 움직이지 않는 구간을 고르고 소리는 같은 장면의 배경 소음으로 바꿉니다.
- **문장 끝이 늘어지거나 글자가 더 붙으면 먼저 이전 테이크에서 자릅니다.** 《换号》 「你本来就没有有」를 다시 만들었더니 「没有了」가 되었고, 이전 테이크를 「没有」 직후에서 자르니 깔끔했습니다.
- **`fix.json`의 `fix`는 배속 후 출력 초입니다.** 원본 초로 채우면 영상이 몇 초 길어집니다.
- **검토 이미지를 낼 때 원본도 함께 둡니다.** 검토용 합본은 칸마다 360×640이라 흐려 보입니다. 1152×2048 원본을 `_review/首帧原图/`에 둡니다.

### 11. 확정

```bash
node scripts/assemble.mjs --work $W --ep $EP --loudnorm --align
```

하드 자막을 입혀 `video/E0N.final.mp4`와 `video/E0N.srt`를 출력합니다. 프레임을 몇 장 뽑아 자막 위치와 글자를 확인합니다.

끝에 `fadeOut`이 있으면 콘티의 해당 회차에 `"tailBlack": 0.5`를 씁니다. 검게 사라진 뒤 순수한 검은 화면과 무음이 0.5초 이어집니다(사용자 요청: 「검은 화면 페이드아웃 잊지 마」). `assemble.mjs`가 회차에 붙이고 하드 자막본에도 그대로 들어가므로 ffmpeg를 따로 돌리지 않아도 됩니다.

**표지**는 두 장입니다: 세로 `封面-竖版.png`(1080×1920)와 가로 `封面-横版.png`(1440×1080, 4:3, 사용자가 11-01에 정함)를 게시할 때 따로 올립니다. 세로는 본편 프레임을 잘라 써도 되고, 가로는 구도가 달라서 인물 시트를 참고 이미지로 걸어 따로 만듭니다. 두 장 모두 두 가지를 갖춰야 합니다:
- `frames.mjs`는 파일 이름에 「横版」이 들어간 그림을 작품 화면비가 아니라 4:3(2048×1536)으로 만듭니다: `frames.mjs fix --raw --target 成片/封面-横版.png`. 만든 뒤 크기를 확인합니다. 《赊账》 첫 시도는 세로로 나왔습니다.
- 표정이 좋아야 합니다. 먼저 썸네일 모음을 만들어 보고, 롱숏이 아니라 가까운 숏에서 고릅니다.
- 한눈에 어느 작품인지 알아봐야 합니다. 이 작품의 표지가 될 요소를 넣습니다: 핵심 소품, 장소, 두 사람의 관계. 잘 나온 얼굴 클로즈업 하나뿐이면 같은 배우의 다른 작품과 겹칩니다(《光坐着》의 두 번째 표지가 《各论各的》와 거의 같았습니다).

뽑은 프레임 중에 맞는 것이 없으면 설정 시트를 참고 이미지로 걸어 따로 한 장 그립니다(`frames.mjs fix --raw`, `--ref`에 장소, 인물, 소품 시트). 배경을 흐리게 하려면 그 그림을 원본으로 `fix`를 한 번 더 하며 「배경에 얕은 피사계 심도, 전경은 그대로」라고 씁니다. 후반에서 흐림을 칠하지 않습니다.

### 12. 정리, 회고

사용자가 확인하면 컷 원본 영상과 중간 파일을 지우고, 완성본, 자막, 영상 생성 기록만 남깁니다. 그다음 `retro-template.md`에 따라 회고를 씁니다: 앞 화와 달라진 점과 그 이유만 적습니다. 규칙이 바뀌었으면 이 reference 문서들을 고칩니다.

**회고 전에 완성본을 숏 단위로 분해합니다.** [reelbench-skills](https://github.com/eternityspring/reelbench-skills)의 `video-shots`로 완성본을 숏별 표로 만들어 작품 폴더의 `_拉片/`에 둡니다. 컷 지점과 길이는 ffmpeg가 재므로 어림하지 않습니다. 숏 크기, 화면, 리듬 역할은 콘택트 시트를 보고 채웁니다.

1. `_拉片/`에서 `video-shots.mjs seed ../成片/<제목>.mp4 --track track.json --title "<제목>" > shots.json`을 실행합니다. 검출된 숏 수를 확인합니다: `video/E0N-*.shots.json`의 컷 수에 끝 검은 화면을 더한 값과 같아야 합니다. 다르면 `recut`으로 나누거나 합칩니다. 같은 카메라, 같은 숏 크기의 이웃한 두 컷은 한 숏으로 합쳐지는 일이 많습니다(《赊账》 s14, s15). 심사판이 출력한 컷 시작 표를 보고 나눕니다.
2. `frames`, `sheet`(a 시트와 b 시트)를 실행하고, 콘택트 시트를 보며 숏 크기, 유형, 카메라, 화면, 대사를 채웁니다. **리듬 역할은 모든 숏에 표시합니다**(훅, 설정, 고조, 강조, 전환, 회수, 숨 고르기, 마무리).
3. `validate --track track.json --frames frames`로 15개 게이트를 모두 통과시킵니다. 그다음 `render --md`와 `render --html --video ../成片/<제목>.mp4`로 `shots.md`와 `shots-report.html`을 만듭니다.
4. 대조 영상이 필요하면 `video-sync.mjs export shots.json --video ../成片/<제목>.mp4 --frames frames -o <제목>-拉片对照.mp4`를 실행합니다(세로 영상은 약 1580×1080, 왼쪽 화면, 오른쪽 숏 목록).

결과는 회고의 「숏 분해」 절에 적습니다: 숏 수, 평균 숏 길이, 분당 컷 수, 리듬 곡선, 가장 긴 숏. 정리할 때 `_拉片/`는 남깁니다(약 15 MB). `panels/`는 다시 만들 수 있으니 지워도 됩니다.

**게시 데이터가 오면 숏 분해와 대조합니다.** 사용자가 6, 24, 72시간 데이터(2초 이탈률, 5초 완주율, 이탈 곡선)를 보내면, 이탈이 뚜렷한 시점을 `_拉片/shots.json`의 숏에 맞춰 회고의 「데이터 대조」에 적습니다: 그 몇 초가 어느 숏인지, 각각 어떤 리듬 역할인지, 왜 떠났는지. 결론이 맞으면 `writing.md`의 규칙으로 만듭니다(《跟谁吃的》가 이렇게 분해한 첫 작품입니다).

## 이야기 언어

이야기는 중국어, 영어, 한국어 중 하나로 쓸 수 있으며, `project.json`에 `"language": "zh" | "en" | "ko"`로 적습니다. 스크립트는 이 값에 따라 다음을 정합니다:

- 대사 길이 계산: 중국어와 한국어는 글자(음절) 수, 영어는 단어 수로 세어 말 속도로 나누고, 말을 시작하는 데 1초를 더합니다.
- 음성 인식에 쓸 언어(`cut.py`가 대사가 끝나는 시점을 잴 때, `assemble.mjs --align`이 자막을 정렬할 때).
- 자막 글꼴과 줄바꿈: 중국어는 글자 단위로, 영어와 한국어는 단어 단위로 줄을 바꿉니다.
- 프롬프트 속 고정 문장(제약, 화면 속 인원, 시선 등)과 대사의 언어 이름.

스크립트가 출력하는 안내도 세 언어로 나옵니다. 기본값은 작품의 이야기 언어를 따르며, 환경 변수 `DRAMAZING_LANG=zh|en|ko`로 지정할 수도 있습니다.

**말 속도는 시험 컷으로 보정해야 합니다.** 중국어 3자/초는 《渡口》 6화에서 나온 값입니다. 영어와 한국어 값은 각각 시험 컷 하나에서 나왔으며 표본이 매우 적습니다(`langs.json`의 `calibrated` 참고). 새 작품의 첫 시험 컷이 나오면:

1. `cut.py --work $W --ep 1 <시험 컷이 있는 세그먼트 번호>`를 실행합니다. 이 세그먼트에 시험 컷만 있어도 실행됩니다. 대사만 재고 세그먼트를 이어 붙이지 않으며, 대사의 시작·끝 초와 「말 속도」(글자 수 또는 단어 수 ÷ 말을 시작해서 끝낼 때까지의 초)를 출력합니다.
2. 이 말 속도가 `langs.json`의 `rate`와 차이가 크면 `project.json`에 `speechRate`를 적습니다. 말 속도에는 문장 사이의 멈춤이 들어 있는데, 이것이 바로 길이를 배분할 때 써야 하는 값입니다.

말 속도가 실제보다 크면 콘티가 대사에 주는 시간이 모자라고, 편집에서 자동으로 길게 남기므로 한 화 전체가 목표 길이를 넘습니다. 작으면 그 반대입니다.

## 의존성

| 도구 | 쓰이는 곳 |
|---|---|
| Node.js 18+ | 모든 `.mjs` 스크립트 |
| Python 3 + Pillow | 편집, 검수, 자막, 미리보기 |
| ffmpeg / ffprobe | 모든 영상 처리 |
| [whisper.cpp](https://github.com/ggerganov/whisper.cpp)(`whisper-cli`) + `ggml-large-v3-turbo`와 `ggml-silero-v5.1.2` 모델 | 대사 길이 측정, 자막 정렬. 모델 폴더 기본값은 `~/models/whisper`이며, 환경 변수 `WHISPER_MODELS`로 바꿀 수 있음 |
| 이미지 도구 하나 | 설정화와 콘티 그림 생성. 참고 이미지를 넣을 수 있어야 함. 실측: Codex CLI |
| 「첫 프레임 + 텍스트 → 영상」 도구 하나 | 영상 생성. 이야기 언어로 대사를 말할 수 있어야 함. 실측: Grok 웹 |
| 글꼴 | 자막과 미리보기. 기본으로 macOS에 들어 있는 글꼴을 씀: 중국어 STHeiti, 영어 Helvetica Neue, 한국어 Apple SD Gothic Neo(`scripts/lang/langs.json` 참고). `project.json`의 `subFont`나 환경 변수 `SUB_FONT`로 바꿀 수 있음. 시스템 글꼴은 상업 사용 불가 |
