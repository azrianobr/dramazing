# Grok 웹에서 영상 생성하기

영상은 Grok 웹판의 영상 생성 기능(Imagine)으로, 정상적인 화면에서 조작해 만듭니다: 첫 프레임을 올리고, 프롬프트를 붙여 넣고, 설정을 고르고, 제출을 누르고, 페이지 자체의 다운로드 버튼으로 내려받습니다.
이 skill에는 웹 자동화 스크립트가 들어 있지 않습니다. Grok / xAI의 이용 약관을 지키고, 스크립트로 페이지의 제한, 심사, 과금을 우회하지 마세요.

## 컷마다 하는 조작

1. Grok의 Imagine 페이지를 열고 「동영상」으로 바꿉니다.
2. 입력창의 업로드 버튼으로 첫 프레임을 올립니다: `frames/<세그먼트 번호>/f<N>.png`. 2 MB가 넘는 PNG는 먼저 약 400 KB의 JPG로 바꿉니다.
3. `video/prompts.json`에서 해당 항목의 `prompt`를 통째로 입력창에 붙여 넣습니다.
4. 설정을 고릅니다:
   - 해상도 1080p.
   - 길이는 이 항목의 `seconds`에 따라 6초, 10초 또는 15초(15초 옵션은 10-11부터 있음).
   - 비율은 작품 화면비: 16:9, 세로 작품은 9:16.
5. 제출을 누릅니다. 6초짜리 컷은 약 1분 30초면 나오고, 10초짜리는 조금 더 걸립니다.
6. 영상이 나오면 페이지의 다운로드 버튼으로 내려받습니다. 파일 이름은 대화 번호입니다(`grok-video-<대화 번호>.mp4`). `ingest.sh $W --file <파일> E01-03-s1`로 하나씩 받아들입니다. 제출할 때 컷 번호와 주소창의 대화 번호를 적어 두어야 나중에 맞출 수 있습니다.

탭을 2~3개 열어 병렬로 진행할 수 있습니다. 탭마다 한 번에 하나씩만 제출합니다.

## 알아 둘 것

- **1080p는 「첫 프레임만 올리고 참고 이미지를 붙이지 않았을 때」만 고를 수 있습니다.** 참고 이미지를 붙이면 720p만 남습니다.
- **길이 설정은 탭끼리 공유됩니다.** 한 탭을 10초로 바꾸면 다른 탭도 10초가 됩니다(《狐月》 s5, s7). 제출할 때마다 길이를 확인합니다.
- **업로드가 멈추면**(썸네일이 회색이고 보내기 버튼이 눌리지 않으면) 페이지를 새로 고치고 다시 올립니다. 연결이 끊겼다가 다시 이어지면 입력창에 이미지가 한 장 더 생길 수 있고, 그러면 해상도가 720p로 떨어집니다. 이때도 새로 고친 뒤 한 장만 올립니다.
- **Grok은 "주체만 바꾸고 동작은 원본 영상과 똑같이"를 하지 못합니다.** 이미지만 받고 영상을 동작 참고로 쓸 수 없습니다. 키프레임 모드에 원본의 초 단위로 쓴 프롬프트를 더해도 중간 프레임의 자세 하나만 고정되고, 나머지 동작의 크기와 박자는 Grok이 채웁니다. 猫踢球(10-13)는 춤 강습 영상의 사람을 고양이로 바꿨습니다. 6초짜리 "浪子踢球"는 대체로 맞았지만 한 구간의 자세가 틀렸고 마무리가 약 0.5초 빨랐으며, 사용자는 보고 나서 포기했습니다. 사용자가 "똑같이"를 원하면 Grok은 비슷한 정도까지만 된다고 먼저 말하고, 전용 동작 전이 도구를 권하세요.
- **업로드가 끝난 뒤에 제출합니다.** 10-21부터 첫 프레임 한 장 업로드에 약 30초가 걸립니다. 썸네일이 뜨기 전에 제출을 누르면 오류도 없이 주소창이 /imagine에 머물고 그 제출은 사라집니다(《随叫随到》 두 번). 주소창이 /imagine/post/…로 바뀌어야 제출된 것입니다.
- **한 번 제출에 영상이 두 개 나올 수 있습니다.** 페이지에 개수 설정은 없습니다. 두 번째 영상이 있으면 기록해 두고 예비로 쓰며, 재작업할 때 먼저 예비를 봅니다.
- **생성 중 미리보기 상자는 언제나 가로입니다.** 세로 영상도 마찬가지이고 가로 영상이 나왔다는 뜻이 아니니, 취소하지 마세요(《老地方》은 3%에서 한 번 잘못 취소했습니다).
- **내려받은 영상은 1920×1088입니다.** 「업그레이드」로 받으면 1904×1072입니다. 편집 스크립트가 모두 작품 화면비의 캔버스(16:9는 1920×1080)로 맞춰 크기를 조정하고 잘라 내므로 손으로 처리할 필요는 없습니다. 세로 영상의 다운로드 해상도는 아직 실측하지 않았습니다.
- **제출한 뒤 영상이 계속 나오지 않고 오류도 없다면:** 대개 첫 프레임이 심사에 걸린 것이고, 흔한 원인은 인물이 미성년자처럼 보이는 것입니다. 심사를 피하려고 방법을 바꿔 가며 다시 제출하지 마세요. 먼저 첫 프레임의 어디가 문제인지(앳된 모습, 표정, 주근깨) 보고, `prompt-rules.md`에 따라 첫 프레임을 다시 그린 뒤 사용자에게 알립니다.
- **「어떤 글자도 넣지 말 것」으로도 자막이 박히는 것을 막지 못합니다.** 대사가 있는 숏에서 Grok이 가끔 대사를 화면에 자막으로 박습니다(《加油》 E01-04/s6). 영상을 수집할 때 매번 화면 아래 3분의 1을 봅니다. 다시 생성하지 않으려면 자막이 나오기 전과 후의 깨끗한 프레임으로 그라데이션 패치를 만들어 덮고, 패치를 사방으로 약 20픽셀씩 키워 자막 상자의 가장자리까지 가립니다. 원본은 따로 보관합니다. 이 문장은 프롬프트 맨 끝에 있을 때 가장 자주 무시됩니다. 그래서 `video-prompts.mjs`는 대사가 있는 숏의 Grok 프롬프트에서 이 문장을 맨 앞에 둡니다(《各论各的》《真的》 두 번 모두 깨끗했음). 프롬프트를 손으로 고칠 때도 맨 앞에 둡니다.
- **인물 하나의 클로즈업에 짧은 대사 한 마디만 있고 동작이 별로 없으면 자막이 가장 잘 박힙니다.** 같은 프롬프트로 다시 제출해도 그대로 박혔습니다(《拍张照》 E01-01/s5, 두 번 연속). 프롬프트를 고쳐 인물에게 계속 이어지는 작은 동작(손가락으로 볼을 톡톡 치기, 눈 깜빡이기, 화면 밖으로 눈길 한 번 주기)을 주니 네 번째는 깨끗했습니다.

## 키프레임 모드와 업그레이드

- **키프레임 모드**: 첫 프레임, 중간 프레임, 마지막 프레임의 세 칸이 있습니다. 중간 프레임은 기본 위치(6초 영상은 3.0초, 10초 영상은 5.0초, 15초 영상은 약 7.3초). 중간 프레임을 먼저 넣고 길이를 바꾸면 표시가 예전 초에 머물 수 있습니다(猫踢球는 10초로 바꾼 뒤에도 "3.0s"로 표시됨). 페이지를 새로 고쳐 다시 올리고, 새 초가 보인 뒤에 시간을 맞추세요에 놓이고, 썸네일을 끌면 전체 순서가 뒤섞입니다. 최고 720p까지만 나옵니다. 마지막 프레임은 구도만 고정하고 얼굴은 고정하지 않습니다. 쓰는 법은 `one-take.md`(《夜馆》)와 `showcase.md`(《狐月》 변신)를 보세요.
  - 10-12 기준 화면: 입구는 「동영상」 옆의 아이콘이며, 더 이상 「+」 안에 있지 않습니다. 올린 이미지는 기본으로 「참고」 역할이 됩니다. 썸네일을 눌러 메뉴에서 첫 프레임, 중간 프레임, 마지막 프레임으로 지정하거나, 첫 프레임 뒤의 빈 칸을 먼저 누른 뒤 올립니다. 세 장 사이에 화살표가 생기고 중간 프레임에 시간이 표시되면 맞습니다. 썸네일을 누르면 입력창에 「Image N」 태그가 들어가니, 프롬프트를 넣을 때 전체 선택해서 바꿉니다.
- **업그레이드 → 1080p**: 영상 페이지의 「업그레이드」 메뉴입니다. 약 30초 걸리고, `generated_video_1080_hd.mp4`(1904×1072)가 하나 더 생깁니다. 화면을 키우기만 하고 프레임 수와 동작은 그대로이므로, 720p에서 정한 편집점을 그대로 쓸 수 있습니다. 키프레임 모드 영상은 먼저 720p에서 만족할 때까지 다듬고, 확정한 뒤 업그레이드합니다.
- **확장**: 시험하지 않았습니다.

## 다운로드가 멈출 때

다운로드 버튼이 계속 돌고 몇 분이 지나도 아무것도 받아지지 않거나, 0바이트 파일이 생기는 경우: 페이지가 Grok의 파일 서버를 기다리는 중이며, 여러 번 누르면 멈춘 요청만 늘어납니다. 실제로 효과가 있었던 방법(《渡口》 1화 리메이크):

1. 다운로드하는 동안 재생 중인 Grok 페이지는 하나만 둡니다. 다른 탭에서 재생 중인 영상은 모두 일시 정지합니다. Imagine 첫 페이지는 예시 영상을 자동 재생하니 다운로드 중에는 열지 않습니다.
2. 다운로드를 한 번 누르고 버튼이 돌기 시작하는지 봅니다. 돌지 않으면 클릭이 먹지 않은 것이니 한 번 더 누릅니다.
3. 돌기 시작하면 5~8분 기다립니다. 그래도 받아지지 않으면 이 페이지를 새로 고치고, 영상을 일시 정지한 뒤 다시 누릅니다. 새로 고친 뒤에는 바로 받아지는 경우가 많습니다.
4. 0바이트 파일은 옮겨 둔 뒤 다시 받습니다. 그대로 두면 다음 파일이 `(1)`이 붙은 이름으로 저장됩니다.
5. 버튼을 눌러도 아무 반응이 없을 때(돌지도 않고 받아지지도 않음, 《各论各的》 E01-01/s1 재작업): 그 페이지에서 스크립트로 영상을 받습니다. 페이지의 `<video>` 주소를 읽어 로그인 정보와 함께 `fetch`하고, 숏 번호를 넣은 이름(`grok-E01-01-s1.mp4`)으로 다운로드하면 `ingest.sh`가 폴더에서 바로 받습니다. 터미널에서 curl로 그 주소를 받으면 403이 납니다. 받은 뒤 `ffprobe`로 길이를 확인합니다.
   - 파일 이름에 이번 배치의 접두어를 붙이고(예: `zd1011b-E01-01-s1.mp4`) 배치마다 바꿉니다. 다운로드 폴더에 다른 작품이 남긴 같은 이름의 옛 파일이 있을 수 있고, `ingest.sh`는 파일을 옮기므로 잘못 수집하면 옛 파일을 덮어씁니다(《真的》).
6. 스크립트의 `fetch`가 끝나지 않을 때: Grok이 열린 다른 탭으로 옮겨 같은 영상 주소를 다시 `fetch`합니다. 《真的》에서 3번 있었고, 매번 다른 탭에서 바로 받아졌습니다.
7. 탭을 바꿔도, 새로 고쳐도, 다운로드 버튼도 안 되고, 전에 받았던 옛 영상까지 안 받아질 때: 멈춘 요청들이 Grok 파일 서버로 가는 브라우저 연결을 다 차지한 것입니다. 병렬로 다시 시도할 때마다 몇 개씩 더 걸려 점점 나빠집니다(《光坐着》 E01-02/s7, 두 탭에 요청 일고여덟 개가 걸려 있었습니다). 순서대로 합니다:
   1. 다른 Grok 탭을 다른 페이지로 이동합니다. 그 탭에 걸린 요청이 끊깁니다.
   2. 지금 페이지를 새로 고치고, 페이지 안 모든 `<video>`의 주소를 지워 플레이어가 스트리밍을 멈추게 합니다.
   3. 약 30초 동안 아무것도 보내지 않고 기다립니다.
   4. `fetch`를 하나만 보냅니다. `.blob()` 전에 상태 코드와 `content-length`를 페이지 변수에 적어 두면 「응답이 아예 없음」과 「데이터가 중간에 멈춤」을 구분할 수 있습니다.
   5. 하나를 다 받은 뒤 다음 것을 받습니다. 병렬로 받지 않습니다.

   이렇게 한 뒤 두 영상 모두 한 번에 받아졌습니다. 요청 하나가 90초가 지나도 응답이 없으면 Grok 쪽 문제이니, 멈추고 몇 분 뒤에 다시 합니다.
8. 페이지 스크립트의 `fetch`가 계속 실패하면 Grok 페이지 자체의 다운로드 버튼으로 돌아갑니다. 《狐月》 s13 재생성본은 스크립트로 두 번 실패했고, 페이지의 다운로드 버튼으로 한 번에 받아졌습니다. 버튼 옆 메뉴에 「동영상 삭제」가 있으니 누르지 않습니다.

## 사용량 기록

Grok의 사용량 페이지(Imagine 페이지의 설정 안)에 이번 주 한도의 비율이 나옵니다. 다음 세 시점에 한 번씩 읽습니다:

1. 시험 컷을 생성하기 전.
2. 일괄 생성을 마친 뒤.
3. 재작업한 뒤.

읽을 때마다 `_logs/usage.tsv`에 한 줄씩 덧붙입니다:

```
시각	이벤트	화	Imagine%	전체%	비고
2026-10-05T07:30	일괄 생성 전	E05	0	0	주간 한도가 막 초기화됨
```

앞뒤 값을 빼면 그 화의 영상 생성 사용량입니다. 참고: 컷 하나에 약 0.2%~0.3%(10초 컷은 더 듦), 컷 30~35개인 한 화에 약 7%~12%입니다. 《渡口》 1화 리메이크: 39번 제출(그중 10초 12개)에 7%를 썼습니다.
